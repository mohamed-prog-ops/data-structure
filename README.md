## 2. Project Overview

This project implements a complete, stack-based mathematical expression evaluator in Python. The system reads mathematical expressions from `input.txt`, evaluates them using classical computer science stack algorithms (Dijkstra's Shunting-Yard algorithm and Postfix Evaluation), and writes the formatted results to `output.txt`.

The project does not use Python's built-in `eval()` or `exec()` functions. All data structures, tokenization routines, precedence rules, and mathematical operations are built from scratch.

## 4. Stack-Based Algorithm Explanation

The evaluation process operates in three distinct phases:

### Phase 1: Tokenization
The input expression string is scanned character by character:
* Multi-digit numbers and floating-point values (e.g., `10`, `3.14`) are grouped into numeric tokens.
* Operators (`+`, `-`, `*`, `/`) and parentheses (`(`, `)`) are recognized.
* Unary operators (e.g., negative numbers or negation) are differentiated from binary subtraction based on preceding token context.

### Phase 2: Infix to Postfix Conversion (Shunting-Yard Algorithm)
Human-readable arithmetic is written in **infix notation** (e.g., `3 + 5 * 2`), where operators sit between operands. To respect operator precedence and parentheses without ambiguity, the expression is converted into **postfix notation** (Reverse Polish Notation, e.g., `3 5 2 * +`):
1. Numbers are sent directly to the output queue.
2. When an operator is encountered, operators with higher or equal precedence on top of the operator stack are popped to the output queue before pushing the current operator.
3. Left parentheses `(` are pushed onto the operator stack.
4. When a right parenthesis `)` is encountered, operators are popped from the stack to the output queue until a matching `(` is found and discarded.
5. Remaining operators on the stack are popped to the output queue at the end.

### Phase 3: Postfix Evaluation
The postfix token list is evaluated using an operand stack:
1. Scan the postfix tokens from left to right.
2. If a token is a number, push it onto the evaluation stack.
3. If a binary operator is encountered:
   * Pop the top two numbers from the stack: second operand $B$ then first operand $A$.
   * Perform the operation: $A \text{ op } B$.
   * Push the computed result back onto the stack.
4. If a unary operator is encountered:
   * Pop the top number, apply the unary operation, and push the result back.
5. When all tokens are processed, the final value on the stack is the expression's result.

## 5. Input and Output Formatting Rules

* **Single Line Mapping**: Each expression line in `input.txt` produces exactly one result line in `output.txt`.
* **No Redundant Echoing**: Output lines contain only computed values or error messages (no original expression or labels).
* **Blank Line Preservation**: Empty or whitespace-only lines in the input are preserved as blank lines in the output.
* **Separator Line Preservation**: Lines consisting of two or more identical characters from `-=_*~#` (e.g., `---`, `===`, `###`, `***`, `~~~`, `___`, `##`, `--`) are recognized as separator lines and preserved unchanged in the exact same line position.
* **Integer Formatting**: Exact whole numbers are formatted as clean integers (e.g., `13`, `16`, `2` rather than `13.0`, `16.0`, `2.0`).
* **Decimal Formatting**: Non-whole numbers are rounded to a maximum of 4 decimal places with redundant trailing zeros stripped (e.g., `1 / 3` $\rightarrow$ `0.3333`, `7 / 8` $\rightarrow$ `0.875`).
* **Negative Zero Guard**: Values evaluating to `-0.0` or `-0` are normalized to `0`.
* **Error Resilience**: Malformed expressions, mismatched parentheses, invalid characters, or division by zero produce clear `Error: ...` messages without crashing the program run.
* **Missing File Handling**: If `input.txt` is missing, an informative message is printed to the console, and execution stops cleanly without creating `output.txt`.

### Note on Assignment Sample Discrepancy:
The assignment brief sample outputs list `17` for the second expression `(8 / 4) + 7 * 2`. 

**Mathematical Verification:**
1. Evaluate inside parentheses: `(8 / 4) = 2`.
2. Evaluate multiplication (precedence over addition): `7 * 2 = 14`.
3. Evaluate addition: `2 + 14 = 16`.

The mathematically correct result is **16**. The program produces the correct mathematical result (16) rather than hard-coding the typo from the assignment brief.

## 8. Error Handling & Edge Cases Handled

* **Empty Stack Operations:** `pop()` and `peek()` on an empty `Stack` instance raise `IndexError`.
* **Division by Zero:** Detected during postfix evaluation and reported as `Error: Division by zero.`.
* **Parentheses Mismatch:** Detects unclosed opening parentheses or unmatched closing parentheses.
* **Malformed Syntax:** Detects consecutive operators, trailing operators, missing operands, or invalid expressions.
* **Invalid Characters:** Detects unsupported characters (letters, unknown symbols).
* **Whitespace Invariance:** Correctly handles expressions with no spaces (`3+5*2`), standard spaces, or irregular spacing.
